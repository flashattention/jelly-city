## 1. 이 프로젝트에서 보여 주고 싶은 것

1. **기록 경쟁 게임에서 "믿을 수 있는 기록"을 만드는 설계**: 점수를 믿지 않고 서버가 플레이를 처음부터 다시 돌려 확인해요. 버전이 다른 클라이언트(토스 미니앱 검수 기간)까지 고려했어요.
2. **실제 데이터를 게임 세계로 바꾸는 파이프라인**: 지도 · 건축물대장 · 실시간 교통을 받아 브라우저에서 60fps 를 목표로 그릴 수 있는 크기로 줄이고, "실제 서울을 걷는 느낌"이라는 감성 목표에 맞게 다듬었어요.
3. **운영하면서 판단하고 되돌리는 과정**: 플레이어 의견 · 지표 · 스크린샷 검수로 결정을 바꾸고, 바꾼 이유를 문서로 남겼어요. 잘못된 결정은 되돌렸어요.
4. **AI 에이전트와 일하는 방식 자체의 설계**: "지시 → 지시서에 구체화 → 하나씩 수행 → 스크린샷 검수 → 커밋" 규칙을 만들고 저장소에 넣었어요.

## 2. 게임 소개

### 2-1. 러너 (본편)

- 곰돌이가 저절로 앞으로 달리고, **좌우 · 점프(2단 = 공중제비) · 숙이기**로 낭떠러지 · 허들 · 가로대 · 가시 · 움직이는 발판을 피해요. 점수 = 거리(m) + 별사탕 × 10.
- **맵 3개**
  - 🌙 **랜덤 꿈나라**: 20초마다 꿈이 바뀌어요(116가지 — 중세 마을 · 사탕 공장 · 끝없는 지하철 · 폐교 …). 하늘 · 안개 · 발판 무늬 · 아래(용암 · 바다 · 구름) · 풍경 · 음악이 함께 바뀌어요.
  - 🔥 **랜덤 지옥**: 더 빠르고, 괴물 주먹 · 용암 같은 위협 (별 × 1.5).
  - 🌌 **랜덤 이공간**: 길은 일자지만 이공간 30가지마다 **물리 규칙이 달라요** — 중력 · 점프 횟수 · 얼음 · 옆바람 · 좌우 반전 · 깜빡이는 발판 · 떨어지는 운석 … (별 × 1.8).
- **모드**: ⚡ 스피드전(순수 실력, 서버 검증 기록만 순위표) · 🎁 아이템전(로켓 · 방어막 · 구름발판 · 자석 · 유령 · 충격파 · 젤리 함정 · 순간이동).
- **난이도 5단계**: 노멀 × 1 · 하드 × 1.55 · 익스트림 × 1.9 · 광속 × 2.85 · 초월 × 3.8 (속도). 별 배율은 1 → 4.5 로 속도보다 가파르게 잡아서 어려운 난이도에 도전할 이유를 만들었어요.
- **같이 달리기**: 최대 12명이 같은 시드로 같은 길을 달려요. 밀치기 · 관전 · 👥 팀전(3분, 가장 멀리 간 팀원이 있는 팀 승리).
- **성장**: 별 → 치장 상점(일반 ~ 초월 7등급, 오라 · 신발 · 발자취 · 점프 효과 …), 업적 611개, 순위 훈장(1 ~ 3위 · 상위 1/5/10%), 명예의 전당, **지금 1위만 낄 수 있는 아이템**.

**걷기 · 움직임**
- WASD + 마우스 시점(오픈월드), Shift 가속(한 번 올리면 멈출 때까지 유지), 3단 점프, 숙이기.
- **모든 건물 벽을 타고 옥상까지**, 다리 · 경사로를 걸어 올라가고 높은 다리 밑을 지나가요. 건물 · 나무 · 사람 · 차 · 전봇대는 뚫리지 않아요.
- 미니맵 · 큰 지도에서 찍어 순간 이동, 바라보는 건물 이름 표시(가려진 건물은 숨김).
- **지역끼리 이어 걷기**: 코스 끝의 빛나는 이정표 문("🎸 홍대 거리 →")으로 걸어 들어가면 이웃 지역의 이쪽 끝에서 이어 걸어요 (여의도 ↔ 홍대 ↔ 신촌, 여의도 ↔ 반포 ↔ 이태원 ↔ 남산 ↔ 명동 ↔ 인사동 ↔ 북촌, 뚝섬 ↔ 성수 · 석촌호수 ↔ 강남).

**실제 데이터로 만든 세계**
- **건물**: 건물마다 실제 외곽선 · 실제 높이 · 공식 이름(단지명 + 동 번호)을 쓰고, 건축물대장의 **용도 · 구조 · 사용승인 연도**로 외벽을 정해요. 예) 80년대 벽돌조 다가구 → 짙은 붉은 벽돌, 90년대 철근콘크리트 근린상가 → 타일 · 화강석, 2010년대 → 모던 패널, 공장 · 창고 → 벽돌 공장, 목구조 낮은 집 → 한옥(기와지붕).
- **가게**: 실제 가게 이름 · 종류(OSM). 실제 이름 간판 · 차양 · 유리문, 들어가서 계산대에서 주문하고 **먹고 가기(자리에서 먹는 동작) / 포장(들고 산책)**. 카페 · 빵집 · 식당 · 치킨 · 피자 · 버거 · 중식 · 일식 · 술집 · 편의점마다 가게 안이 달라요. 홍대만 들어갈 수 있는 가게 약 1,700곳.
- **거리**: 보도블록 · 연석 · 노란 겹줄 · 흰 점선 · 교차로 횡단보도 · 번갈아 바뀌는 신호등 · 실제 도로 이름 파란 도로명판 · 골목 전봇대와 처진 전깃줄 · 세워 둔 스쿠터.
- **지하철**: 실제 위치 · 번호의 출구(서울 지하철 출구 모양 · 노란 번호판) → 대합실(개찰구 · 발매기 · 도착 안내판) → 호선별 승강장(스크린도어 · 이전/다음 역 이름판) → **열린 문으로 타면 호선별 열차 안**(의자 색 · 노약자석 · 임산부석 · 노선도 · 안내 화면 · 흐르는 터널 불빛)을 지나 다음 역에 내려요.

**실시간 서울**
- 🚇 **지하철**: 역 안 열차가 실제 도착 정보(○○방면 · 남은 초)에 맞춰 들어오고, 바깥 철교(한강철교 1호선 · 동작대교 4호선 · 동호대교 3호선 · 당산철교 2호선 …)를 지나는 열차도 실제 위치를 따라요.
- 🚌 **버스**: 내 주변을 지나는 실제 시내버스를 실제 GPS 위치대로(간선 파랑 · 지선 초록 · 노선 번호판). 정류장에 선 버스에 타면 실제 노선대로 가요.
- 🚗 **도로 · 사람 · 날씨**: 길 위 승용차 · 택시 · 트럭은 **한 대 한 대의 위치가 실제는 아니에요**(개별 차 위치는 공개 자료가 없어요). 서울 도시데이터의 도로 소통(원활 · 서행 · 정체)과 속도 · 출퇴근 시간에 맞춰 **차 수와 빠르기**만 실제를 따라요. 지역 혼잡도(행인 수) · 실제 날씨(비 · 하늘)도 따라요.
- 🕹️ **직접 운전**: 길 위 차 · 버스 · 오토바이는 물론 실시간 버스도 빼앗아 몰 수 있고(내 화면에서만, 내리면 실제 자리로), 지하철은 맨 앞 운전실에서 선로를 따라 직접 몰아요(가속 · 제동 · 앞뒤, 역에 서면 문 열림).

**감성**
- 하루 흐름(1분 = 1시간) · 계절(벚꽃 · 신록 · 단풍 · 눈) · 날씨. 블룸 · 색감 보정 · 틸트 시프트 후처리.
- 잎 카드로 만든 나무와 바람에 흔들리는 풀, 하늘을 비추는 유리 건물, 밤에 용도마다 다른 창 불빛(집은 노란빛 · 회사는 하얀빛 · 시간대별 켜짐).
- 사람: 지역마다 다른 사람들 — 여의도 회사 근처엔 양복 직장인, 홍대엔 스트리트 패션 · 코스프레, 공원엔 가족 · 연인 · 피크닉, 벚꽃 철엔 연인이 가득.

### 지도 파이프라인 (`tools/hangang-map.mjs`)

1. **코스**: 실제 자전거길 · 거리 이름(예: `한강남자전거길`, `어울마당로`)의 OSM 조각을 이어 한 줄로 만들고, 경도 범위로 잘라요. 조각이 끊긴 곳은 범위 안 조각만 먼저 골라 40m 까지 이어 붙여요(반포).
2. **지형 · 길 · 다리 · 철교**: 같은 기준점(위도 37.53 · 경도 126.98)으로 서울 어디든 같은 좌표계라, 지역끼리 나중에 이어 붙일 수 있어요.
3. **건물**: OSM 외곽선 + 브이월드 건물(공식 층수 · 이름) + 브이월드 **건축물 정보**(용도 · 구조 · 사용승인일 · 실제 높이)를 외곽선 안 점 검사로 맞춰요. 예) 홍대 3,707채 중 3,395채에 건축물 정보.
4. **가게 · 역 · 출구 · 골목 · 도로 이름**을 함께 담아요.
5. **줄이기**: 좌표를 코스 중심 기준 0.1m 정수로, 거리 지역은 코스에서 600m 넘게 먼 낮은 건물을 빼요(홍대 17,800 → 3,700채).
6. Overpass 가 바쁘면(429 · 502 · 503 · 504) 거울 서버 세 곳을 돌아가며 다시 시도하고, 받은 자료는 `.cache/` 에 기억해요.

### 그리기 · 성능

- **재질별로 한 덩어리**: 건물은 외벽 종류(아파트 · 유리 · 석재 · 벽돌 · 거리 상가 · 공장 · 한옥 …)마다 하나의 메시로 합치고, 외벽 무늬는 캔버스로 그린 8 × 8 칸 텍스처를 반복해요. 밤 불빛은 같은 칸의 발광 텍스처.
- **글씨는 그림 한 장(atlas)**: 간판 · 네온 · 도로명판 · 벽화를 2048px 그림 한 장에 256개씩 모아 그리기 호출 1번으로.
- **같은 물체는 인스턴스**: 나무 · 신호등 · 전봇대 · 화분 · 스쿠터 · 자물쇠 · 침목.
- **멀면 숨기기**: 출구 · 동 번호는 400m, 행인 곰은 70m 밖이면 숨겨요. 행인 · 차는 그림자 계산에서 빼요.
- 결과: 그리기 호출 여의도 1,108 → 약 300, 홍대 896 → 약 330, 홍대 버스킹 자리 1,225 → 636.
- **역 · 가게 · 몰 · 전망대 안**: 바깥 세상과 겹치지 않게 아주 먼 좌표에 따로 짓고, 들어가 있는 동안 바깥을 숨겨요(로딩 화면 없이 바로 전환).

## 4. 판단 기록 (문제 → 근거 → 결정 → 결과)

전체 기록은 [의사결정 기록](docs/dream-runner/의사결정.md)에 있어요. 여기서는 포트폴리오로 보여 주고 싶은 판단을 골랐어요.

### 공정성 · 운영

**① 점수를 믿지 않고 플레이를 다시 돌려 본다**
- 문제: 브라우저 콘솔로 속도 · 점수를 바꿔 기록을 올릴 수 있었어요.
- 근거: 러너의 콘텐츠는 순위표예요. 조작된 1위 하나가 생기면 나머지는 도전할 이유가 없어져요.
- 결정: 판마다 시드가 정해져 있어 같은 입력이면 같은 결과가 나와요. 클라이언트는 **프레임 시간과 입력만** 보내고, 서버가 같은 게임 코드로 처음부터 다시 달려 거리 · 별을 직접 계산해요. 출발표(서버 서명) 없는 기록은 받지 않고, 출발표 하나로 별 · 기록 · 통계는 한 번만 처리해요.
- 결과: 거리를 20m 늘린 기록은 거절되고 정상 기록은 통과하는 것을 확인. 테스터가 찾은 구멍 3개(기록 없이 점수만 보내기 · 출발표 빼고 별 또 받기 · 재전송으로 통계 두 번)도 막았어요.

**② "느리게 돌리기" 조작과 느린 폰을 구분하기**
- 문제: 게임 시계 자체를 늦추면 입력은 진짜라 다시 돌려 봐도 결과가 맞아요.
- 결정: 실제로 흐른 시간보다 게임 시간이 크게 짧은데, 느린 기기에서 생기는 프레임 막힘 흔적이 없으면 의심으로 표시해요. 막지 않고 운영자에게 올려요.
- 판단: 정상 플레이어(특히 느린 폰)를 잘못 막는 비용이, 의심 기록 하나를 사람이 보는 비용보다 크다고 봤어요.

**③ 예전 버전 클라이언트의 기록 (토스 미니앱 검수 2 ~ 3일)**
- 문제: 서버는 최신 코드로 다시 돌려 보는데, 미니앱은 검수 때문에 예전 버전으로 돌 수 있어요.
- 검토: 버전마다 코드를 저장소에 쌓기(손이 많이 가고 빠뜨리기 쉬움) vs **서버가 켜질 때 배포된 코드를 자동 보관**(선택).
- 결과: 기록은 그 판을 달린 버전의 코드로 확인해요. 덤으로, 웹에서 한 판 도중에 배포가 돼도 기록이 통과하게 됐어요. 미니앱 번들은 그 버전이 서버에 보관돼 있어야 만들어져요.

**④ 사업자 등록 없이 출시하기 · 순위표 나누기**
- 토스 로그인은 사업자 등록 뒤에만 가능 → **기기 계정**을 자동으로 만들고, 나중에 토스 계정을 그 기기 계정에 연결(아이디가 그대로라 기록 이전 불필요, 설정값 `TOSS_LOGIN=1` 하나로 켬).
- 토스 사용자는 웹 순위표와 **따로**: 웹 상위권은 수백 판을 달린 사람들이라, 새 사용자에게는 새 경쟁판이 더 동기를 준다고 판단.

### 게임 디자인

**⑤ 이공간 30가지: "어렵지만 반드시 깰 수 있게"**
- 겉모습만 다른 맵 30개가 되지 않게, 맵마다 **물리 규칙 하나**를 바꿨어요.
- 자동 플레이 봇(빔 탐색)으로 노멀 · 광속 · 초월에서 30개 모두 끝까지 갈 수 있는지 확인 → 초월에서 못 깬 얼음 지그재그 구간을 찾아 넓혔어요.

**⑥ 되돌린 결정: 모바일 숙이기**
- 모바일 의견으로 숙이기를 "누르는 동안만"으로 바꿨다가 **되돌렸어요**. 숙이기는 PC와 같은 게임 코드라, 바꾸면 PC 감각과 기존 기록의 조건이 함께 바뀌어요. **기록 경쟁 게임에서 기기마다 · 갑자기 규칙이 바뀌면 안 된다**는 원칙을 세웠어요(지금은 저장소 규칙 파일에도 적혀 있어요).

**⑦ 상위 아이템은 "확 달라 보이게", 기본 난이도는 하드로**
- 최상위 아이템이 하위 아이템 색만 바꾼 것처럼 보이던 문제 → 전설 · 신화 · 초월에 연출 단계를 따로 두고 하위를 낮추는 대신 상위를 끌어올림. 1위 전용 아이템은 1위를 뺏기면 바로 못 끼게 해서 "지키는 경쟁"도 만들었어요.
- 노멀은 처음 온 사람에게도 심심해서 첫 판 기본값을 하드로.

### 서울 산책

**⑧ 실시간 공공데이터는 서버가 받아 기억하고, 모두가 그것을 읽는다**
- 문제: 지하철 · 버스 · 도시데이터 API 는 호출 수 제한이 있고 키가 노출되면 안 돼요.
- 결정: 키는 서버 환경변수에만. 서버가 15초(지하철) ~ 3분(버스, 부를 때마다 2개 노선만 새로) ~ 5분(도시데이터) 기억하고, 모든 클라이언트는 서버 것을 읽어요. 실패하면 마지막 값을 돌려줘요.
- 결과: 접속자가 늘어도 공공 API 호출 수는 그대로예요.

**⑨ "틀 찍어내기" 금지 → 건물마다 실제 정보로**
- 문제: 처음엔 "교회 = A형태, 빌딩 = B형태"처럼 종류별 틀을 썼고, 플레이어(=저)가 "실제 한강을 걷는 느낌이 안 난다"고 판단했어요.
- 결정 1: 이름난 건물은 **위성사진(브이월드) · 실제 사진을 보고 손으로** 모습을 적어 넣는 틀(`LANDMARKS`)을 만들었어요. 예) 63빌딩(위로 갈수록 좁아지는 금빛 유리), IFC(비스듬한 유리 왕관), 파크원(연회색 핀 · 붉은 기둥), 순복음교회(둥근 본관 · 세로 조명 · 정면 탑 · 십자가), 전경련 컨퍼런스센터(은색 달걀), 자벌레, N서울타워.
- 결정 2: 수천 채를 다 손으로 할 수는 없어서, **건축물대장의 용도 · 구조 · 사용승인 연도**로 외벽을 정해요. "그 건물의 실제 정보"로 다르게 보이게 한 거예요.
- 결정 3: 사진은 보는 용도로만 쓰고 **게임에 넣지 않아요**(저작권). 텍스처는 모두 코드로 그려요.

**⑩ 지시가 쌓이면 품질이 흩어진다 → 작업 방식을 바꿨다**
- 문제: 하루에 지시가 수십 개 쌓이면서, 에이전트가 일부만 하고 "다 끝났다"처럼 보고하거나, 중간마다 멈춰서 물어보는 일이 생겼어요.
- 결정: 모든 지시를 [작업 지시서](docs/dream-runner/한강맵-작업지시서.md)에 **"무엇을 · 어디에 · 어떤 모습 · 어떻게 확인"** 수준으로 구체화하고, `[ ]` / `[~]` / `[x]` 로 표시하며 하나씩 수행 → 스크린샷 검수 → 커밋하는 규칙을 [CLAUDE.md](CLAUDE.md) 로 저장소에 넣었어요.
- 결과: "다 했냐"고 물으면 지시서의 빈칸이 바로 답이 돼요. 새 지시는 먼저 지시서에 반영돼요.

**⑪ 느려 보이는 건 속도가 아니라 프레임 문제였다**
- 문제: "홍대에서 기본 속도가 느리고 다시 느려졌다"는 의견.
- 원인: 한 프레임 시간을 0.05초로 자르는데(러너 규칙), 무거운 지역에서 프레임이 20 아래로 떨어지면 이동이 실제로 느려졌어요.
- 결정: 서울 산책에서는 0.1초까지 허용(러너 규칙은 그대로 — ⑥의 원칙), 그리고 무게 자체를 줄였어요(먼 건물 · 그리기 호출 · 그림자 · 먼 곰). 그리기 호출 1/3 ~ 1/6.
- 함께 찾은 버그: 거리 계산이 "가장 가까운 구간"이 아니라 "기준보다 가까운 첫 구간"을 돌려줘서 코스 옆 건물까지 지워지고 있었어요.

**⑬ 데이터를 믿되 확인한다 — 한옥 구조 코드**
- 북촌을 만들었더니 한옥 마을이 붉은 벽돌 동네로 보였어요. 건축물대장의 목구조 코드를 41 ~ 49로 잘못 알고 있었던 것.
- 북촌 단층 집들의 실제 코드 분포를 뽑아 보니 대부분 **51(일반목구조)** → 코드 범위를 고치고, 정보가 없는 단층 작은 집도 한옥 마을에서는 한옥으로. 스크린샷으로 기와지붕 무리가 나타나는 것을 확인.
- 교훈: 외부 데이터로 모습을 정할 때는, 결과 화면이 실제 동네와 맞는지 **반드시 눈으로** 본다.

**⑭ 배포 실패 메일 — 코드가 아니라 도구 내려받기**
- "run failed" 메일이 반복돼 확인해 보니, 실패 원인은 모두 배포 도구(flyctl) 내려받기 서버의 504 였어요(코드 · 테스트는 통과). 커밋이 잦아 다음 배포가 모두 반영하고 있었지만, 설치와 배포를 각각 여러 번 다시 시도하도록 CI 를 고쳤어요.

**⑫ 지형을 다루지 않는 엔진으로 산 정상 만들기 (남산)**
- 엔진은 땅이 평평하다고 가정해요. 산 전체를 언덕으로 바꾸는 대신, **정상 광장을 높이 0 으로 두고 서울을 발아래(-228m)로 내리는** 방식으로 풀었어요. 숲 비탈 · 전망대(140m, 유리창 밖으로 진짜 서울)를 그 위에 얹었어요.

## 5. 검증 방법

| 무엇을 | 어떻게 |
|---|---|
| 기록 공정성 | 서버가 같은 게임 코드로 입력을 다시 돌리기 · 조작 기록(거리 +20m) 거절 확인 · 출발표 재사용 · 재전송 테스트 |
| 맵 클리어 가능 여부 | 자동 플레이 봇(빔 탐색)으로 이공간 30개 × 난이도 3개 완주 확인 |
| 새 물체 · 장면 | **헤드리스 크롬 + 시험 페이지**로 카메라 위치 · 시각(낮 · 노을 · 밤) · 계절을 정해 스크린샷 → 실제 사진 · 위성사진과 비교 → 고치고 다시. 이 과정에서 찾은 예: 밤에 건물이 하얗게 날아감, 간판 글씨 좌우 반전, 다리 바닥이 위에서 투명, 분수 위치가 강 위, 네온이 너무 드묾 |
| 성능 | 시험 페이지에서 그리기 호출 수 · 삼각형 수 · 장면 물체 종류별 개수를 세어 무거운 것부터 줄이기 |
| 실시간 API | 운영 서버의 `/api/seoul/*` 응답을 직접 확인 (예: 여의도역 9호선 "전역 출발 100초") |
| 배포 | CI 가 문법 검사 → 서버 기동 → 모든 게임 페이지 · 순위표 API 확인 → Fly.io. 지도 파일이 없는 지역은 고르기에 안 보이게(HEAD 확인) |

## 🐻 2. 젤리시티

말랑한 **곰돌이 젤리들이 사는 3D 도시**에서 동료들과 함께 살아가는 멀티플레이 라이프 시뮬레이션이에요. 3인칭으로 걷고, 날고, 차를 빼앗아 운전하고, 건물에 들어가고, LLM으로 대화하는 이웃 젤리들과 친해질 수 있어요. 모든 접속자가 같은 시간 · 같은 날씨의 한 도시에 살아요.

### 도시 생활
- **캐릭터**: 젤리 색 · 눈 · 코 · 입 · 볼터치 · 날개 · 액세서리를 골라 나만의 젤리를 만들어요(메인 화면의 캐릭터 관리와 같아요). 고른 색이 다른 플레이어 화면에서도 똑같이 보이고, 맞으면 그 색 젤리가 튀어요.
- **48종 건물**에 모두 들어갈 수 있어요. 시청에서 직업을 고르고 일하면 돈 · 경험치, 부동산에서 주택 · 빌라 · 아파트를 사면 열쇠를 받고 대표 집에서 부활해요.
- **욕구**: 포만감 · 재미 · 사교 · 청결 + 체력. 편의점 · 피자 · 치킨 · 중국집 · 국밥 · 카페 등에서 먹고 가거나 포장해요. 음식마다 실제로 먹는 모션이 달라요(숟가락 · 젓가락 · 손 · 컵째로).
- **LLM 이웃**: 시민 140명이 이름 · 직업 · 성격 · 가족 · 꿈을 갖고 하루를 살아요. 말을 걸면 지금 하는 일, 몸 상태, 나와의 친밀도, 예전 대화 기억을 바탕으로 gpt-4o-mini가 대답해요. 기분이 나쁘거나 맞으면 112에 신고해요.
- **휴대폰**: 카메라 · 갤러리 · 젤리그램(댓글 · 팔로우 · DM) · 말랑팅(매칭) · 문자 · 112 · 지도 · 훈장 · 건의함.
- **레벨 · 퀘스트 · 훈장**: 만렙 없는 레벨, 게임 날짜마다 오늘의 퀘스트 4개, 이름표 아래 훈장(재산 · 사냥 · 명사수 · 자동차 …).
- **즐길 거리**: TV 7채널과 영화관, 낚시 22종과 매운탕 · 횟집, 클럽 · 사격장 · 말랑 도장, 이모트 휠(J 꾹)과 공식 챌린지 노래에 맞춘 춤(주변 플레이어도 같은 노래를 들어요).

### 넓은 세계 · 탈것
- **2.3km 세계**: 도시 · 계곡 · 젤리산 · 야생의 숲 · 사냥꾼 들판 · 악어 늪지대 · 호랑이 정글 · 아마존 · 바다 · 대교 · 섬 목장 마을 · 🐉 드래곤 협곡.
- **이동**: 날기(Space 두 번) · 벽 타기(옥상까지) · 수영 · 대쉬 · 2단 점프.
- **탈것**: 자동차 21종(스포츠카 5종) · 자전거 · 스쿠터 · 오토바이 · 전차 · 헬기. 쇼룸에서 사고 차 키로 불러요. 가로등 · 나무를 들이받으면 부서져요.
- **동물 포획**: 모든 동물에 체력바가 있고, 절반 아래로 깎은 뒤 Z로 타이밍을 맞추면 포획해서 타요. 길의 🐎 도시 말은 E로 바로 올라타고(털색 4가지 · 안장 · 고삐), 탄 동안 화면에 'F 내리기'가 늘 보여요. 드래곤은 날면서 화염방사 · 불덩이를 써요.
- **🎢 젤리랜드 놀이공원**: 롤러코스터 · 바이킹 · 관람차 · 회전목마를 실제로 타요. 모든 플레이어 화면에서 같은 시각에 같은 모습으로 움직여요.

### 전투 · 경찰 · 거대 젤리
- **무기**: 근접무기(등급별 휘두르기 이펙트 · 빛 막대), 총 20여 종(실제와 비슷한 사거리 · 위력 · 반동, 우클릭 1인칭 조준, 저격총 스코프), 활 · 석궁, 마법봉 7종, 수류탄 · 로켓. 헤드샷은 한 방이에요.
- **수배와 경찰**: 시민 · 플레이어가 112에 신고해야 경찰이 와요. 경범죄는 체포(하늘에 있으면 경찰도 날아와요) → 교도소 60초, 중범죄는 경찰 · 군대 · 전차 · 헬기가 출동해요.
- **거대 젤리의 습격**: 접속하면 작은 · 중간 · 큰 거대 젤리가 도로를 따라 도시를 걷고, 30초마다 하나씩 늘어나요(최대 10마리). 머리 위 체력바가 있고, 총 · 마법은 튕겨 나가요.
- **🪝 하늘갈고리 장비**: 우클릭으로 갈고리를 건물 · 거대 젤리에 박고 꾹 누르면 당겨져 날아가요(떼면 그 기세로 날아감, 건 동안 Space 가스, 놓으면 바로 2단 점프로 옥상 올라서기). 좌클릭 쌍검으로 뒷목(빨간 과녁)을 베야 쓰러져요. 작은 건 한 번, 클수록 여러 번. 1인칭에선 X자 쌍검 궤적이 눈앞에 보이고, 장비를 들면 3인칭 카메라가 조금 가까이 와요.

### 🖥️ 그래픽 설정 (상단 🖥️ 그래픽 · ⚙️ 설정 단추)

상단 단추에 지금 단계(상 · 중 · 하, 자동이면 '(자동)')가 보이고, 누르면 이 컴퓨터 사양(그래픽 카드 · CPU 코어 · 메모리 · 화면)과 왜 그 단계가 골라졌는지 나와요. 추천과 상관없이 거기서 바로 자동 · 상 · 중 · 하를 고를 수 있어요.

처음엔 **자동**이에요. 그래픽 카드 · CPU 코어 · 메모리를 보고 단계를 고르는데, 원만한 플레이를 위해 **사양이 낮아도 '중' 이상**으로 시작해요. '상'에서 플레이 중 6초 평균이 30fps 아래로 떨어지면 '중'으로 낮추고, '중'에서도 느리면 '하'로 바꿔 볼지 알림으로 물어봐요(추천하진 않지만 컴퓨터 성능상 '하'가 맞을 수도 있어요). 직접 고른 '상'이 느리면 '중'을 먼저 권해요. 📈 FPS 표시를 켜면 오른쪽 아래에 지금 fps와 단계가 나와요.

| 단계 | 추천 컴퓨터 | 바뀌는 것 |
|---|---|---|
| 상 | 맥북 M1 이상 · 외장 그래픽(지포스 GTX 1060 · 라데온 RX 580 이상) 데스크톱 · 게이밍 노트북 | 선명한 화면(최대 2배) · 부드러운 그림자(2048) · 계단 현상 없애기 · 시민 130m · 동물 220m |
| 중 | 내장 그래픽 미니PC · 노트북(라데온 680M · 780M, 인텔 Iris Xe · Arc · UHD), 아이패드 — 사양이 낮아도 기본은 중 | 화면 1배 · 단순한 그림자(1024) · 시민 100m · 동물 170m · 숲 소품 짧게 |
| 하 | 추천하지 않아요 · '중'에서도 렉이 심할 때만 (인텔 N100 · 셀러론 · 오래된 노트북 · 저가 태블릿 · 휴대폰) | 화면 0.75배 · 그림자 끔 · 계단 현상 없애기 끔 · 시민 75m · 동물 130m |

계단 현상 없애기는 새로고침(F5)해야 바뀌어요. '하'에서도 느리면 크롬 설정 → 시스템 → **그래픽 가속 사용**이 켜져 있는지 확인하세요(꺼져 있으면 CPU로 그려서 아주 느려요).

전체 기능은 [`docs/기능정리.md`](docs/기능정리.md)에 정리되어 있어요.

- **혼자 하기 · 맵 연습**: 젤리봇과 바로 한 판(모두 8 · 12 · 16 · 20명), 처음 화면에서 맵 이름을 누르면 그 맵 하나만 연습. **같이 하기**: 최대 20명 방.
- 코스 · 장애물은 씨앗과 시간으로 정해져서 모두의 화면이 같아요(`public/jelly-rumble/js/rounds.js`). 몸 움직임(`phys.js`)은 내 화면과 서버 봇이 같은 파일을 쓰고, 통과 · 탈락 · 떨어지는 판 · 터진 문은 서버가 정해요.
- 조작: WASD 이동(카메라 기준) · Space 점프 · Shift/E 다이브 · 화면 클릭 후 마우스로 카메라 · M 소리. 휴대폰은 왼쪽 막대 · 오른쪽 끌기 카메라 · 점프/다이브 단추.

## 🍓 14. 젤리 머지

곰젤리를 병에 떨어뜨려 같은 맛끼리 닿으면 한 단계 큰 젤리로 합쳐지는 물리 퍼즐이에요(체리 → … → 콜라 → 👑 무지개 왕곰 11단계, 왕곰 둘이 만나면 '젤리 대폭발').

- **병 3종**: 🫙 네모 병 · 🥣 둥근 그릇 · 🍸 깔때기 컵. 위험선을 2.6초 넘게 넘으면 끝.
- **켜고 끄는 설정**: 🎯 떨어질 자리(점선 · 바닥 동그라미 · 합쳐질 젤리 표시, 나만 적용) · 💥 폭탄 젤리(닿고 잠시 뒤 펑) · 🌈 무지개 젤리(어떤 젤리와도 합쳐져 한 단계 올림). 폭탄 · 무지개는 방 전체에 같게(방장이 정함).
- **콤보**: 1.3초 안에 이어 합치면 점수가 늘어요.
- **혼자 하기**(병마다 🏆 순위표 — 로그인 · 체험판 · 비로그인 임시 닉네임) · **봇과 대결** · **같이 하기**(최대 8명, 모두 같은 젤리 순서). 큰 젤리 · 콤보를 만들면 상대 병에 🍬 설탕 덩어리가 떨어지고(2.2초 예고 · 내가 먼저 공격하면 상쇄), 설탕은 옆에서 합치거나 무지개에 닿으면 녹아요. 오른쪽에 라이벌 병이 실시간으로 보여요.
- 물리 엔진(`public/jelly-merge/js/engine.js`)은 화면과 서버 봇이 같이 써요. 조작: 마우스 클릭 · 휴대폰 끌다가 떼기 · ← → / A D + Space.

## 🍮 15. 젤리궁정

숨은 역할을 지키며 젤리를 던지는 4~7명 카드 대결이에요.

- **역할**: 👑 젤리왕(공개) · 🛡️ 근위대(왕 편) · 😈 말썽꾼(왕을 녹이면 승리, 서로 몰라요) · 🦊 여우(혼자 편 — 두 명을 녹이거나 왕이 녹을 때 마지막까지 남기). 인원마다 역할 구성 · 왕 체력이 달라요.
- **설탕 🍬**: 차례마다 설탕 +2(최대 6) · 카드 2장. 카드마다 설탕 값을 내고 써요. 한 차례 30초 · 막기 응답 7초.
- **거리**: 둥근 탁자에서 몇 자리 떨어졌는지. 녹은 자리는 빠지고, 🔄 자리 바꾸기로 거리가 바뀌어요.
- **카드 18종**(젤리 던지기 · 탄산 폭탄 · 매운 젤리 · 방울 막기 · 딸기 시럽 · 파티 케이크 · 끈적 꿀 · 슬쩍 · 수정 젤리 · 자리 바꾸기 · 설탕 충전 · 선물 상자 · 장비 6종) · **캐릭터 9종**(능력 하나씩).
- 8바퀴째부터 차례마다 ❤️ 이 1씩 녹아 판이 늘어지지 않아요. 녹은 사람의 역할은 공개.
- 서버가 판정하고 손패 · 몰래 본 역할은 주인에게만 보내요. 나간 자리는 젤리봇이 이어받아요. 📖 규칙 창 · 숫자키 1~9 카드 · Enter 차례 끝 · Space 막기.

## 🔔 16. 젤리 땡

차례대로 젤리 카드를 뒤집다가 **한 맛의 곰젤리 수가 가운데 목표 숫자와 딱 같으면 종을 치는** 순발력 게임이에요. 글자 입력 없이 키 두 개면 돼요.

- 카드: 🍓 딸기 · 🍋 레몬 · 🍈 메론 · 🫧 소다 · 🍇 포도 곰젤리 1~5마리. 각자 맨 위 카드만 세요.
- **F / ↓** 뒤집기(가만히 있으면 저절로), **Space / J / Enter** 땡! 맞으면 깔린 카드를 모두 가져가고 목표 숫자가 바뀌어요. 틀리면 모두에게 1장씩.
- 특수 카드(켜고 끄기): 🌟 황금곰(보이면 바로 땡) · 🌈 무지개곰(모든 맛 +1) · 🍋 시큼젤리(보이는 동안 치면 무조건 헛땡).
- 카드가 없으면 탈락, 마지막까지 남거나 시간(2 · 3 · 5분)이 끝났을 때 카드가 가장 많으면 우승.
- 종 순서는 서버가 정해요(먼저 온 것부터 잠깐 모은 뒤 핑을 감안해 가장 빠른 사람). 젤리봇은 사람처럼 늦게 반응하고 가끔 헛땡도 쳐요. 휴대폰은 큰 단추 두 개.

## 🧸 17. 젤리 슬라이드

판 전체를 한 방향으로 밀어 같은 단계의 젤리곰끼리 부딪히면 한 단계 큰 곰이 되는 퍼즐이에요(체리 → … → 👑 무지개 왕곰 11단계, 왕곰 둘이면 '젤리 대폭발' +5000 · 판의 설탕이 모두 녹아요).

- **판 크기**: 4×4(빠르고 아슬아슬) · 5×5(넓게 오래).
- **🍬 설탕 덩어리**: 움직이지 않는 벽이라 줄을 끊어요. 바로 옆에서 합치기가 일어나면 녹아요.
- **🌈 무지개 젤리**: 가끔 나와서 어떤 곰과 부딪혀도 그 곰을 한 단계 올려요. 무지개 · 설탕은 켜고 끌 수 있어요(방에선 방장).
- **콤보**: 한 번 밀어 여러 번 합치면 콤보마다 점수 +50%.
- **혼자 하기**: 판 크기마다 🏆 순위표 · 한 판에 한 번 되돌리기(Z).
- **봇과 대결 · 같이 하기**(최대 8명, 같은 씨앗): 큰 곰 · 3콤보 · 대폭발을 만들면 상대 판에 설탕이 떨어져요(경고 띠로 미리 보이고 내 공격으로 막을 수 있어요). 라이벌 작은 판이 실시간으로 보이고, 시간이 끝나면 점수 순.
- 엔진(`public/jelly-slide/js/engine.js`)은 화면과 서버 봇이 같이 써요. 조작: ← → ↑ ↓ / WASD, 휴대폰은 판을 쓱 밀기.

## 🫥 18. 젤리 숨바꼭질

술래가 눈을 가린 사이 **내 곰돌이(다른 게임과 같은 젤리 곰돌이) 몸에 직접 색을 칠해** 벽 · 바닥 · 물건과 똑같아지고, 술래는 1인칭 **물감총**으로 수상한 곳을 쏴서 찾는 3D 숨바꼭질이에요.

- **판 흐름**: 역할 카드 → 숨기(45 · 60 · 90초) → 찾기(90 · 120 · 180초) → 판 결과 → 술래를 바꿔 다음 판 → 최종 순위. 판 수는 "모두 한 번씩" 또는 2 · 3 · 5판.
- **칠하기(F)**: 곰돌이를 끌어서 칠하기(붓 3가지 · 18색 · 주/보조 색), **💧 스포이드**(화면 색이 아니라 그 겉면 무늬의 실제 색 · 무늬를 찍음), 부위별 · 전체 채우기, 무늬 도장(줄무늬 · 체크 · 땡땡이 · 물결 · 꽃 · 별 · 찍어 온 무늬), 되돌리기. 눈 · 코 · 입도 그 자리를 칠하면 칠한 색으로 덮여 얼굴까지 숨길 수 있어요.
- **자세**: 서기 · 쪼그리기 · 납작 · 동글이 + Q/E 돌기. **위장도 % 계기판**이 둘레 겉면과 내 몸 색을 비교해 보여 줘요.
- **술래**: 숨는 동안은 눈 가림 화면, 찾을 땐 **물감총** — 클릭하면 물감이 포물선으로 날아가고 꾹 누르면 연사, 젤리에 맞으면 찾았다! 빗나간 물감은 벽 · 바닥에 자국으로 남아 모두에게 보여요. 물감통은 12발이고 조금씩 다시 차요. 찾는 동안 움직이는 젤리는 느려지고 반짝이 흔적이 남아요. 들킨 젤리는 구경꾼이 돼요.
- **점수**: 숨는 쪽은 버틴 시간 + 끝까지 숨으면 보너스, 술래는 찾은 수 + 다 찾으면 남은 시간 보너스.
- **맵 3종**: 🧸 장난감 방 · 🍭 사탕 가게 · 🌷 꽃 정원 — 50~60m 넓이에 무늬 있는 가구 · 블록 더미 · 탁자 · 깔개 120~140개.
- **조작**: WASD 이동 · 화면을 한 번 클릭하면 마우스로 바로 둘러보기(Esc 로 커서) · F 칠하기(칠할 땐 커서가 나와요).
- **혼자**: 🫥 숨기 연습(봇이 술래) · 🔍 술래 연습(봇이 숨음). **같이**: 최대 10명, 사람이 적으면 젤리봇이 채워요. 칠한 몸 그림은 작은 JPEG 로 다른 화면에 그대로 보여요.
- 서버가 단계 · 시간 · 찾기 거리 · 점수 · 물감 중계(연사 제한)를 정해요. 젤리봇은 겉면 무늬를 따라 칠하고, 술래 봇은 시야 · 거리 · 위장도 · 움직임으로 알아채 다가가서 물감총을 쏴요(실력만큼 맞혀요).
- 휴대폰: 막대로 이동 · 손가락으로 칠하기 · 🔫 물감총 단추(꾹 누르면 연사).

## ⚔️ 19. 젤리 아레나

탑 · 미드 · 정글 · 바텀 · 서폿으로 나뉘어 상대 기지의 **젤리 심장**을 부수는 5 대 5 전략 배틀이에요. 빈 자리는 젤리봇이 채워요 (쉬움 · 보통 · 어려움). 한 판은 15~25분쯤이에요.

- **챔피언 20명**: 탱커 · 전사 · 암살자 · 마법사 · 원거리 · 서포터. 챔피언마다 지속 효과 + Q W E R 기술 + 주문 2개 (번쩍 + 자리별 강타 · 회복 · 점화).
- **맵**: 길 3개 · 강 · 정글 네 구역 · 수풀 · 전장의 안개. 강을 기준으로 정확히 대칭이에요.
- **건물**: 길마다 포탑 3개 → 수문 → 심장 지킴이 2개 → 젤리 심장. 앞 건물을 부숴야 뒤를 칠 수 있고, 꼬마 없이 치면 피해가 크게 줄어요. 수문을 부수면 슈퍼 꼬마가 나와요.
- **CS · 성장**: 꼬마를 마지막 한 대로 잡아야 금화! 레벨 15까지 · 기술 찍기 · 기지 상점(아이템 19종 · 추천 순서).
- **정글**: 숲 12곳에 여섯 종류(늑대 · 개구리 · 골렘 · 집게게 · 박쥐 · 달팽이), 강에 도망치는 퐁당 오리. **벌레왕**(3분~, 왕꿀벌 · 달빛 나방 · 강철 장수벌레 · 불꽃 반딧불이, 잡으면 영구 강화, 셋이면 왕관) · **거대 곰팡이왕**(8분, 2분 강화) · **태고의 별 거북**(15분쯤, 2분 30초 동안 체력 낮은 적 마무리). 큰 몬스터는 바닥에 표시를 그리고 내려치는 패턴이 있어요.
- **서버가 계산**: 경기 전체를 서버(`server/jelly-arena/sim.js`)가 20Hz 로 계산하고, 팀마다 보이는 것만 보내요. 나간 사람 자리는 봇이 이어 받아요.
- **조작**: 우클릭 이동 · 공격, Q W E R (누르면 범위, 떼거나 좌클릭으로 발사, 우클릭 취소 · 🎯/⚡ 단추로 즉시 발사), D F 주문, A 공격 이동, Shift 챔피언만 노리기, C 사거리, B 상점, Tab 점수판, Y 카메라 고정, Alt+클릭 알림.
- **조작감**: 경기 중 마우스는 화면 안에 갇혀요(Pointer Lock + 직접 그린 커서, Esc 로 풀기). 내 캐릭터는 서버 답을 기다리지 않고 바로 움직이고(예측 이동), 공격 준비 중 이동하면 취소돼 치고 빠질 수 있어요. 끝나기 직전에 누른 기술은 기억했다가 나가고, 사거리 밖 대상 기술은 걸어가서 써요.

- **패치노트**: 메인에 들어오면 마지막으로 본 뒤 바뀐 내용이 가운데 창으로 떠요(새것이 없으면 안 떠요). 메인의 📜 패치노트에서 모든 게임을, 각 게임 처음 화면의 📜 패치노트에서 그 게임 기록을 봐요. `public/shared/patchnotes.json` 에 지난 기록이 있고, 배포할 때 CI 가 새 커밋을 덧붙여요(`tools/patchnotes.mjs`). 커밋 제목과 `- ` 줄이 그대로 플레이어에게 보이니 플레이어 말로 쓰고, 숨길 커밋은 본문에 `[노트없음]` 을 적어요. docs · ci · chore 등은 빠지고, 작성자는 공개하지 않으며, 옛 게임 이름은 새 이름으로 바뀌고, 다른 작품 이름이 든 줄은 빠져요.
- **메인 화면(`/`)**: 로그인 · 닉네임 · **내 캐릭터 관리**(만들기 · 꾸미기 · 삭제 · ⭐ 대표). **👒 옷 · 모자 꾸미기**: 모자 26 · 얼굴(안경 등) 18 · 옷 24 · 소품 17 가지가 모든 게임에서 보여요(젤리시티에서 같은 자리 장비를 끼면 장비가 먼저). 만든 캐릭터를 모든 게임에서 쓰고, 방 · 결과 화면에 내 곰돌이 얼굴이 나와요.
- **로그인 없이도**: 캐릭터를 이 기기에 만들고 꾸밀 수 있어요(최대 4개, `public/shared/js/local-chars.js`). 방 만들기 · 빠른 참가 · 초대 코드 · 기록 남기기(임시 닉네임)도 다 돼요. 젤리시티만 계정(구글 · 체험판) 캐릭터로 해요.
- **방 · 초대**: 6자리 초대 코드 · 링크 복사. 한글 자판 그대로 쳐도 코드가 영문으로 들어가요.
- **방 채팅**(`public/shared/js/chat.js`): 대기실부터 게임 중까지. Enter 로 열고 쓴 뒤 다시 Enter 로 보내고 닫혀서 바로 게임에 집중. 내역은 왼쪽 아래에 흐리게 계속 보여요. 팀전이면 📢 전체 / 👥 팀(Tab) 전환, 들어오고 나가는 안내, 젤리봇 인사.
- **닉네임**: 구글 계정은 실명 대신 직접 정한 닉네임만 보여요.
- **🏆 순위표**: 드림 러너 · 젤리드리프트 · 젤리텐 · 젤리 서바이버 · 젤리 타자연습 · 젤리 머지 · 젤리 슬라이드. 계정마다 판별 최고 기록 하나, 체험판 · 비로그인(임시 닉네임)도 올라가고, 서버가 기록을 다시 확인해요.
- **ESC**: 열린 선택창(무기 고르기 · 큰 지도 · 조작법) · 순위표 · 방 목록을 닫아요.
- **소리**: 처음 화면 · 방 · 게임 중 🔊 단추(M). 음악 · 효과음은 모두 Web Audio 로 합성해서 음원 파일이 없어요.

## 만든 방식과 검증

한 사람이 **무엇을 만들지 · 어떤 제약을 둘지 · 결과가 맞는지**를 정하고, 구현 · 테스트 · 배포는 AI 코딩 에이전트(Claude Code)가 맡았어요(커밋 대부분이 `Co-Authored-By: Claude`). 서로 겹치지 않는 게임은 에이전트 여러 개가 동시에 만들고, 공용 파일(서버 경로 · 메인 화면)은 한 곳에서만 고쳐 충돌을 막았어요.

에이전트가 만든 결과도, 게임 속 LLM 판정도 그대로 믿지 않고 **다시 돌려 볼 수 있는 테스트**로 확인한 것만 배포해요.

| 검증 | 방법 · 예 |
|---|---|
| 브라우저 플레이 | 헤드리스 크롬(CDP)으로 실제 게임을 조작 · 스크린샷 · 콘솔 오류 수집 (방 만들기 · 초대 참가 · 옛 주소 이동 · 기록 남기기) |
| 빠른 시계 시뮬레이션 | 서버 코드를 가짜 시계로 수천 판 돌려 영웅 · 맵 승률, 판 길이, 오류를 측정 — 예: 점령전 공격팀 승률 76~84% → 출발 지점 · 점령 시간 조정 후 50~57% |
| 규칙 점검 | 젤리수호대 기술 84가지 자동 점검, 젤리궁정 봇끼리 인원별 3,000판(끝나지 않는 판 0), 젤리대소동 맵마다 봇 16마리로 완주율 · 낙하 위치 측정 |
| 물리 회귀 | 빠른 돌진에 얇은 벽 뚫림 · 벽 위로 올라서기 같은 버그를 수치 테스트로 재현 → 고친 뒤 같은 테스트로 확인 |
| LLM 회귀 | 끝말잇기 판정 기준을 바꿀 때 고정 낱말 목록(인정 · 거절)으로 실제 모델을 다시 확인하고 캐시 버전을 올림 |
| 배포 검사 | CI 가 문법 검사 → 서버 기동 → 모든 게임 페이지 · 옛 주소 리다이렉트 · 순위표 API 를 확인해야 배포 |

## 실행 (로컬)

서버는 Node.js(20 이상)로 돌아가요. Node가 없으면 Docker로 실행하면 됩니다.

```bash
# Docker (권장)
cp .env.example .env        # OPENAI_API_KEY 등 입력
docker compose up --build   # → http://localhost:8000

# 또는 Node가 있다면
npm install
OPENAI_API_KEY=sk-... npm start
```

| 환경변수 | 설명 |
|---|---|
| `GOOGLE_CLIENT_ID` | 구글 로그인용 OAuth 클라이언트 ID. 없으면 개발용 이름 로그인 (로컬 `npm start` 에서만) |
| `OPENAI_API_KEY` | NPC 대화 · 끝말잇기 판정 · 그림 맞히기용 키. 없으면 기본 대사 · 너그러운 판정 · 그림 맞히기 꺼짐 |
| `ADMIN_EMAILS` | 건의함을 볼 수 있는 관리자 구글 이메일 (쉼표로 여러 명). 휴대폰 📮 건의함 또는 `/admin.html` |
| `GAME_PASSWORD` | 입장 비밀번호 (선택). 비워 두면 누구나 입장 |
| `OPENAI_MODEL` | 기본 `gpt-4o-mini` |
| `OPENAI_BASE_URL` | OpenAI 호환 API를 쓸 때 |
| `TIME_SPEED` | 젤리시티 현실 1초당 게임 분 (기본 1.5) |
| `DATA_DIR` | 세계 · 기록 저장 위치 (기본 `./data`, Docker는 `/data`) |
| `STREET_CHAT_PER_MIN` | NPC끼리 거리 수다를 LLM으로 만드는 횟수 상한 (분당, 기본 6) |
| `WORLD_DROPS` | 젤리시티 거리에 떨어져 있는 무기 개수 (기본 14) |
| `REDIRECT_TO` | 설정하면 모든 요청을 이 주소로 보내요 (서버 이전 후 옛 주소용) |

개발용 URL 파라미터: `?autostart&name=이름` (개발용 로그인일 때 시작 화면 건너뛰기)

## 로그인

- **구글 로그인**: 계정마다 캐릭터 4개까지(서버에 저장, 젤리시티의 돈 · 집 · 아이템도 함께).
- **체험판**: '체험판으로 시작'으로 구글 없이 계정을 만들어요. 이틀 동안 접속하지 않으면 사라져요.
- **로그인 없이**: 젤리시티를 뺀 모든 게임을 바로 할 수 있어요(캐릭터는 이 기기에 저장).

### 구글 로그인 설정
1. [Google Cloud Console](https://console.cloud.google.com/apis/credentials) → **사용자 인증 정보 만들기 → OAuth 클라이언트 ID**
2. 애플리케이션 유형: **웹 애플리케이션**
3. **승인된 JavaScript 원본**에 `https://jelly-city.fly.dev` 와 `http://localhost:8000` 추가 (리디렉션 URI는 필요 없음)
4. 처음이면 OAuth 동의 화면을 **외부 / 테스트** 로 만들고, 같이 할 동료 이메일을 테스트 사용자로 추가 (또는 앱 게시)
5. 발급된 클라이언트 ID(`....apps.googleusercontent.com`)를 `GOOGLE_CLIENT_ID` 로 설정. 클라이언트 보안 비밀번호는 쓰지 않아요

## 배포 (Fly.io + GitHub 자동 배포)

세계 상태(시계, NPC, 차량, 동물)와 게임 방이 서버 메모리에 있으므로 **서버는 반드시 1대**로 돌려야 해요. WebSocket을 지원하는 곳이어야 하고, 정적 호스팅으로는 안 됩니다.

처음 한 번만 설정하면, 이후에는 `main` 브랜치에 push할 때마다 GitHub Actions가 문법 검사 · 서버 기동 · 모든 게임 페이지 응답을 확인하고 실서버에 배포해요 (`.github/workflows/deploy.yml`).

```bash
# 1) 처음 한 번: 앱 만들기 (fly.toml의 app 이름을 바꿨다면 그대로 커밋)
brew install flyctl && fly auth signup
fly launch --copy-config --no-deploy
fly volumes create roach_data --size 1 --region nrt
fly secrets set GOOGLE_CLIENT_ID=....apps.googleusercontent.com OPENAI_API_KEY=sk-... ADMIN_EMAILS=나@gmail.com
fly deploy

# 2) GitHub에 배포 권한 주기 (앱 이름이 바뀌면 토큰도 새로 만들어야 해요)
fly tokens create deploy -a jelly-city
# GitHub 저장소 → Settings → Secrets and variables → Actions → FLY_API_TOKEN 에 저장

# 3) 이후로는 push만 하면 배포
git push origin main
```

- 배포하는 동안 서버는 세계 · 기록을 저장하고 재시작돼요. 젤리시티는 몇 초 뒤 자동으로 같은 캐릭터로 다시 접속하고, 다른 게임은 '서버 업데이트 중… 20초 안에 복구돼요' 안내가 떠요.
- 머신은 꼭 1대로 유지하세요 (`fly scale count 1`).
- 서버를 옮길 때: 옛 서버의 `/data`(world.json, photos, 기록 파일)를 새 서버에 옮기고, `world.json`을 `/data/import.json`으로 두고 재시작하면 그걸로 세계를 복원해요. 옛 앱에는 `REDIRECT_TO`를 설정해 새 주소로 보내요.

### Render
`render.yaml`로 Blueprint 배포도 할 수 있어요. 무료 플랜은 잠들고 디스크가 없어 재시작하면 세계가 초기화되니 starter 플랜과 디스크를 쓰세요.

### 비용과 보안
- NPC 대화 · 끝말잇기 판정 · 그림 맞히기는 서버의 OpenAI 키로 과금돼요(gpt-4o-mini). 끝말잇기 판정은 저장해 두고, NPC 거리 수다 · 그림 맞히기는 횟수를 제한해요.
- 키는 서버에만 있고 브라우저로 전달되지 않아요. 로그인 · 기록 제출은 요청 횟수를 제한하고, 점수 · 기록은 서버가 다시 확인해요.
