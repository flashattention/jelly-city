# 드림 러너 의사결정 기록

운영하면서 생긴 문제를 **문제 → 근거 → 결정 → 결과** 순서로 남긴 기록이에요. 모든 변경은 git 커밋으로 남아 있어요.

---

## 1. 순위표 조작: "기록을 믿을 수 있어야 경쟁이 된다"

- **문제**: 브라우저 콘솔에서 게임 속도나 점수를 바꿔 기록을 올릴 수 있었어요.
- **근거**: 러너 게임의 콘텐츠는 순위표예요. 조작된 1위 하나가 생기면 나머지 사람은 도전할 이유가 사라져요.
- **결정**: 점수를 믿지 않고 **플레이를 다시 돌려 봐요**. 판마다 시드가 정해져 있어서 같은 입력이면 같은 결과가 나와요. 클라이언트는 프레임 시간과 입력만 보내고, 서버가 같은 게임 코드로 처음부터 다시 달려서 거리 · 별을 직접 계산해요.
- **결과**: 순위표 기록은 서버가 확인한 것만 올라가요. 확인이 애매한 기록(서버가 바쁠 때 등)은 막지 않고 운영자 화면에 올려 사람이 봐요.

## 2. QA에서 찾은 구멍 3개

- **문제**: 테스터가 세 가지를 찾아 줬어요.
  1. 플레이 기록 없이 점수만 보내면 올라갔어요.
  2. 출발표를 빼고 보내면 별을 또 받을 수 있었어요.
  3. 같은 요청을 다시 보내면 판수 통계가 두 번 쌓였어요.
- **근거**: "애매하면 일단 받고 나중에 사람이 본다"는 원칙이 오히려 구멍이 됐어요.
- **결정**: 출발표와 플레이 기록을 **필수**로 바꿨어요. 출발표 하나에 별 · 기록 · 통계를 한 번씩만 처리하고, 같은 요청이 다시 오면 처음 결과를 그대로 돌려줘요. 사용한 출발표는 서버를 다시 켜도 기억해요.
- **결과**: 정상 기록은 그대로 통과하고, 거리를 20m 늘린 기록은 거절되는 것을 확인했어요.

## 3. 느리게 돌리기 조작

- **문제**: 게임 시계 자체를 늦추면 입력은 진짜라서 다시 돌려 봐도 결과가 맞아요.
- **근거**: 이 경우 "게임 속 시간"은 "실제로 흐른 시간"보다 한참 짧아요. 다만 느린 폰도 비슷하게 보여서, 느린 폰과 구분해야 했어요.
- **결정**: 실제 시간보다 게임 시간이 크게 짧은데, 느린 기기에서 생기는 프레임 막힘 흔적이 없으면 의심으로 표시해요. 기록은 받되 운영자에게 알려요.
- **결과**: 정상 플레이어는 막지 않으면서 조작 의심만 사람이 확인해요.

## 4. 토스 미니앱의 예전 버전 기록

- **문제**: 기록 확인은 서버의 최신 게임 코드로 해요. 그런데 미니앱은 검수(2 ~ 3일) 때문에 예전 버전으로 돌 수 있어서, 그동안의 기록이 모두 "결과가 다르다"로 거절될 위험이 있었어요.
- **검토한 방법**:
  - 버전마다 코드를 직접 저장소에 쌓기 → 손이 많이 가고 빠뜨리기 쉬워요.
  - **서버가 배포된 코드를 버전마다 자동 보관** ← 선택
- **결정**: 서버가 켜질 때마다 지금 게임 코드를 보관하고, 기록은 그 판을 달린 버전의 코드로 확인해요. 미니앱 번들을 만들 때 그 버전이 서버에 있는지 먼저 확인해서, 배포 전 코드로는 번들을 못 만들게 했어요.
- **결과**: 웹에서 한 판 도는 도중에 배포가 돼도 기록이 통과하게 됐어요 (덤으로 얻은 개선).

## 5. 사업자 등록 없이 토스 미니앱 내기

- **문제**: 토스 로그인은 사업자 등록 뒤에만 쓸 수 있어요. 로그인이 없으면 기록 · 별을 저장할 수 없었어요.
- **근거**: 출시를 미루면 지표를 모을 수 없어요. 인앱 광고는 누적 수익 5천 원까지 사업자 없이 가능해요.
- **결정**: 처음 열면 **기기 계정**을 자동으로 만들어 기록을 남기고, 나중에 토스 로그인이 열리면 토스 계정을 그 기기 계정에 **연결**해요. 아이디가 그대로라 기록을 옮기는 작업이 필요 없어요.
- **결과**: 사업자 등록 전에도 출시할 수 있고, 등록 후에는 설정값 하나(`TOSS_LOGIN=1`)로 토스 로그인을 켜요.

## 6. 미니앱 순위표를 웹과 따로 두기

- **문제**: 토스 사용자를 웹 순위표에 넣을지 따로 둘지 정해야 했어요.
- **근거**: 웹 순위표 상위권은 수백 판을 달린 사람들이에요. 새로 온 토스 사용자는 처음부터 순위권에 들 수 없어서 경쟁 동기가 약해져요.
- **결정**: 계정 · 기록 · 별을 따로 관리해요. 게임 코드는 하나로 두고, 서버 저장소만 나눴어요.
- **결과**: 토스 사용자에게는 새 경쟁판이 열리고, 웹 기록은 그대로 보존돼요.

## 7. 이공간 맵: "어렵지만 반드시 깰 수 있게"

- **문제**: 꿈나라보다 훨씬 어려운 세 번째 맵을 30가지 만들면서, 너무 어려워 아예 못 깨는 구간이 생길 위험이 있었어요.
- **결정**:
  - 길은 모두 일자로 두고, 대신 이공간마다 **물리 규칙 하나**를 바꿨어요 (중력 · 점프 횟수 · 얼음 · 바람 · 좌우 반전 등). 겉모습만 다른 맵 30개가 되지 않게 하려는 거예요.
  - 자동 플레이 봇으로 노멀 · 광속 · 초월에서 30개 모두 끝까지 갈 수 있는지 확인했어요.
- **결과**: 봇이 초월에서 못 깬 얼음 지그재그 구간을 찾아 간격과 폭을 넓혔어요. "끝없는 반전" 맵은 화면 전체가 아니라 분홍 발판 위에서만 좌우가 뒤집히게 바꿨어요 (플레이어 의견).

## 8. 모바일 조작 개선과 되돌린 결정

- **문제**: 모바일 좌우 버튼이 불편하다는 의견, 터치하다 화면이 파랗게 선택되는 문제, 숙이기가 짧게 눌러도 0.75초 유지되는 게 어색하다는 의견이 있었어요.
- **결정**: 좌우 버튼 → 조이스틱 → 원형 조이스틱(사방으로 움직이지만 좌우만 반영). 점프 버튼은 숙이기의 오른쪽 위 대각선으로 옮기고, 화면 선택과 길게 누르기 메뉴를 막았어요.
- **되돌린 것**: 숙이기를 "누르는 동안만"으로 바꿨다가 되돌렸어요. 숙이기 규칙은 PC와 같은 게임 코드라, 바꾸면 PC 플레이어의 감각과 기존 기록의 조건이 함께 바뀌어요. **기록 경쟁 게임에서는 기기마다 규칙이 다르거나 규칙이 갑자기 바뀌면 안 된다**고 판단했어요.

## 9. 닉네임을 바꾸면 예전 기록 이름도 바뀌게

- **문제**: 닉네임을 바꿔도 순위표 · 게시판에는 예전 이름이 남았어요.
- **근거**: 순위표는 "누가 1위인가"를 보여 주는 곳이라, 같은 사람이 이름 두 개로 보이면 혼란스러워요.
- **결정**: 기록에는 계정 아이디만 믿고, 이름은 **보여 줄 때마다 지금 이름**으로 바꿔 끼워요. 단, 캐릭터로 달린 기록은 닉네임이 아니라 그 캐릭터 이름으로 보이고, 캐릭터 이름을 바꾸면 따라 바뀌어요 (플레이어 의견으로 수정).

## 10. 처음 온 사람의 기본 난이도: 노멀 → 하드

- **문제**: 노멀은 처음 해 보는 사람에게도 너무 쉬워서, 첫 판의 인상이 심심했어요.
- **결정**: 처음 들어온 사람은 하드로 시작하고, 그다음부터는 마지막에 고른 난이도로 시작해요.

## 11. 상위 아이템은 "확 달라 보이게"

- **문제**: 1위 · 초월 10,000m 같은 최상위 아이템이 하위 아이템의 색만 바꾼 것처럼 보였어요. 예를 들어 '초월 정상의 길'이 '무지개 길'의 연한 버전처럼 보였어요.
- **근거**: 얻기 어려운 아이템의 가치는 남이 보고 바로 알아보는 데서 나와요.
- **결정**: 전설 · 신화 · 초월에 연출 단계(1 ~ 3)를 따로 두고, 단계마다 효과를 더해요. 하위 아이템을 덜 예쁘게 만드는 대신 상위 아이템을 끌어올렸어요. 1위 전용 아이템은 1위를 뺏기면 바로 못 끼게 해서, 지키는 경쟁도 생기게 했어요.
