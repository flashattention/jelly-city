# 보안 강화 작업지시서

2026-11-13 지시: "다 되면 젤리러너를 포함한 젤리시티 게임들의 보안을 한층 강화하는 패치를 진행해 줘. 이상한 유형의 사이버 공격이나 유저들의 AI를 이용한 다양한 케이스의 공격에 대비할 수 있게."

- **순서:** 지금 하는 서울 산책 지시서 작업이 끝난 뒤 시작한다.
- **원칙:**
  - 서버가 모든 것을 정한다. 브라우저가 보내는 값은 믿지 않고, 말이 되는지 서버가 다시 본다.
  - 막을 때는 정상 플레이어가 억울하지 않게 한다. 애매하면 막지 말고 기록해 사람이 본다(드림 러너 기록 확인 방식과 같다).
  - 비밀 키는 브라우저 · 로그 · 응답 · AI 프롬프트에 절대 나가지 않는다.
- **"AI 를 이용한 공격"의 뜻:** AI 로 만든 가짜 클라이언트 · 자동 플레이 봇, 대량 생성 글 · 이름, 젤리시티 이웃 AI 대화에 넣는 프롬프트 주입 · 탈옥, AI 로 빠르게 찾은 API 허점 조합.
- **확인:**
  - 로컬 서버(임시 DATA_DIR)에 공격 시나리오 시험 스크립트를 돌린다. 운영 서버에는 시험하지 않는다.
  - 막는 것마다 `node --test` 시험을 남긴다.
  - 정상 플레이(드림 러너 한 판 · 방 게임 한 판 · 게시판 글 · 젤리시티 대화)가 그대로 되는지 본다.

## 1. 점검: 공격 지도
- [ ] 1-1 서버의 모든 입구를 표로 만든다.
  - 대상: HTTP API(`server/index.js` api · 게임별 `*Api`), 웹소켓 14종(`/arcade-ws` 등), 정적 파일, 사진.
  - 입구마다 적을 것: 누가 쓰나(로그인 · 체험판 · 익명) · 받는 값 · 크기 제한 · 속도 제한 · 서버 확인 여부.
  - 표 아래에 빈 곳(제한 없음 · 확인 없음)을 위험도 순으로 적고, 2 ~ 12 항목에 반영한다.

## 2. HTTP 공통
- [ ] 2-1 보안 헤더를 모든 응답에 붙인다.
  - `X-Content-Type-Options: nosniff`, `Referrer-Policy: strict-origin-when-cross-origin`, `Strict-Transport-Security`.
  - `Content-Security-Policy`: 쓰는 출처(자기 도메인 · cdn · 구글 로그인 · 토스)만 허용. 처음엔 Report-Only 로 깨지는 곳을 찾고, 그다음 켠다.
  - `frame-ancestors`: 토스 미니앱 등 허용한 곳만.
- [ ] 2-2 정적 파일 경로 넘어가기를 막는다.
  - `..`, 인코딩한 `%2e%2e`, 역슬래시, 널 문자로 `public/` 밖(.env · server/ · data)을 읽을 수 없게 한다.
  - 숨김 파일(.git · .env)은 404 로 응답한다.
- [ ] 2-3 요청 본문 · 시간 제한.
  - 모든 POST 가 크기 제한이 있는 `readJson` 을 거친다.
  - `headersTimeout` · `requestTimeout` 으로 천천히 보내는 공격(slowloris)을 끊는다.
- [ ] 2-4 JSON 오염 막기.
  - `__proto__` · `constructor` · `prototype` 키가 든 본문을 버린다.
  - 저장할 때는 필요한 키만 골라 옮긴다(받은 객체를 통째로 Object.assign 하지 않기).
- [ ] 2-5 오류 응답에 내부 정보(스택 · 경로 · 키 이름)를 넣지 않는다.

## 3. 속도 제한(공통 모듈)
- [ ] 3-1 IP + 계정(또는 익명 id) 기준 토큰 버킷 모듈을 하나 만들어 모든 쓰기 API 에 붙인다.
  - 지금은 게시판 · 기록 · 판수에 따로따로 있다.
  - 넘치면 429 와 "잠시 후 다시" 안내를 준다.
- [ ] 3-2 웹소켓 접속 수 제한: IP 하나당 동시 접속 · 1분당 새 접속 상한.
- [ ] 3-3 웹소켓 메시지 속도 제한: 종류별 초당 상한, 넘으면 버리고 계속 넘으면 끊는다.
- [ ] 3-4 방 만들기 · 초대 코드 맞히기 제한: 코드를 무작위로 대입하는 공격을 막는다.

## 4. 웹소켓 입력
- [ ] 4-1 Origin 확인: 자기 도메인 · 토스 미니앱 · 로컬 개발만 업그레이드를 허용한다.
- [ ] 4-2 메시지 꼴 확인: 게임마다 받는 메시지 종류 · 필드 형 · 숫자 범위(NaN · Infinity · 거대 값) · 글자 길이를 공통 검사기로 본다.
- [ ] 4-3 오래 조용한 접속 · 핑 없는 접속을 끊는다.

## 5. 점수 · 기록 위조 (AI 로 만든 가짜 클라이언트 · 자동 봇)
- [ ] 5-1 순위표가 있는 게임 모두(드림 러너 · 드리프트 · 젤리텐 · 서바이버 · 타자 · 머지 · 슬라이드 · 아케이드)를 점검한다.
  - 볼 것: 출발표(티켓) · 실제 지난 시간 · 다시 돌리기 확인이 있는지.
  - 없는 게임은 최소한 출발표 + 시간 · 점수 상한 + 같은 출발표 재사용 금지를 넣는다.
- [ ] 5-2 사람 같지 않은 입력 찾기: 입력 간격이 기계처럼 일정함, 반응 시간이 사람 한계보다 빠름, 끝없이 완벽함.
  - 바로 막지 않는다. 비상 리포트(관리자 화면)에 올리고, 상위권이면 순위표 반영을 보류한다.
- [ ] 5-3 같은 계정 · IP 에서 기록을 짧은 시간에 아주 많이 올리면 막고 기록한다.

## 6. 경제(별 · 출석 · 뽑기 · 업적)
- [ ] 6-1 별을 주는 모든 곳에 하루 상한 · 같은 요청 두 번 주기 금지(idempotency)가 있는지 본다.
  - 대상: 판 끝 · 광고 보너스 · 출석 · 혼자 하기 업적(`/api/cos/solo`) · 뽑기.
- [ ] 6-2 익명 id 를 대량으로 새로 만들어 별 · 업적을 찍어 내는 것을 막는다.
  - 익명 id 는 IP 당 하루 새로 만드는 수에 상한을 둔다.
  - 익명 id 의 별은 계정으로 옮길 때 상한을 둔다.
- [ ] 6-3 혼자 하기 끝 알림 남용: 30초 ~ 30분 조건에 더해 하루 횟수 상한을 둔다. 시작 없이 끝만 오는 요청은 버린다.

## 7. 계정 · 세션 · 익명 id
- [ ] 7-1 익명 id 는 비밀번호와 같다. 순위표 · 공개 응답 · 다른 사람에게 가는 방 정보에 익명 id 가 나가지 않는지 확인한다.
- [ ] 7-2 구글 로그인 토큰 확인: aud(클라이언트 id) · iss · 만료를 본다. 세션 토큰은 충분히 길고 무작위이며, 만료와 로그아웃 시 폐기가 있는지 본다.
- [ ] 7-3 관리자 기능: `isAdmin` 이 필요한 모든 경로를 서버에서 확인하는지, 관리자 행동은 로그에 남는지 본다.

## 8. 글 · 이름 · 채팅 (AI 대량 생성 · 사칭)
- [ ] 8-1 XSS 점검: 게시판 · 댓글 · 닉네임 · 캐릭터 이름 · 채팅 · 방 이름이 화면에 들어가는 모든 `innerHTML` 에 이스케이프가 되는지 전수 확인한다(`esc`).
- [ ] 8-2 보이지 않는 글자 · 방향 바꾸기 글자 · 비슷한 모양 글자로 사칭하는 것을 막는다.
  - 대상: 제로폭 · RTL 오버라이드 · 결합 문자 남용.
  - '운영자' · '관리자' · '젤리게임즈' 를 흉내 낸 이름을 막는다.
- [ ] 8-3 AI 대량 글 막기: 같은 · 거의 같은 글 반복, 짧은 시간 많은 글, 링크 · 연락처 · 광고 패턴을 막는다. 새 계정 · 익명은 더 엄격하게.
- [ ] 8-4 신고가 쌓이면 자동으로 숨기고 관리자가 본다(지금 방식 점검).

## 9. 젤리시티 이웃 AI 대화 (`server/jelly-city/llm.js`)
- [ ] 9-1 프롬프트 주입 · 탈옥 대비.
  - 사용자 말은 지시가 아니라 대화 내용으로만 다룬다(구분 표시).
  - 시스템 프롬프트 · 키 · 서버 정보를 묻거나 역할을 바꾸려는 시도에는 캐릭터대로 넘긴다.
  - 다른 플레이어 이름 · 채팅이 프롬프트에 들어가는 곳(간접 주입)도 같은 처리를 한다.
- [ ] 9-2 비용 공격 막기: 사람 · IP 당 분당 · 하루 호출 수, 입력 길이, 출력 최대 토큰을 제한한다. 전체 하루 예산을 넘으면 기본 대사로 넘어간다.
- [ ] 9-3 출력 확인: 키 · 내부 정보 패턴, 개인정보, 유해한 말이 나오면 걸러 기본 대사로 바꾼다.
- [ ] 9-4 주입 시험 문장 30개 이상(한국어 · 영어 · 섞어 쓰기 · 역할극 · 인코딩)으로 시험해 결과를 표로 남긴다.

## 10. 서버가 바깥을 부르는 곳 (`server/seoul.js` 등)
- [ ] 10-1 SSRF 막기: 사용자가 준 값이 바깥 요청 주소 · 매개변수에 그대로 들어가지 않게 한다. 지역 · 노선 · 역 이름은 허용 목록으로만 받는다.
- [ ] 10-2 키가 로그 · 오류 · 응답에 찍히지 않는지 확인한다.
- [ ] 10-3 바깥 응답 꼴 확인(캐시 오염 막기): 이상한 값은 버리고 지난 값을 쓴다.

## 11. 의존성 · 비밀 · 배포
- [ ] 11-1 `npm audit` 를 돌려 위험한 패키지를 올린다(동작 확인).
- [ ] 11-2 저장소 기록 전체에서 비밀 키 · 토큰이 들어간 적이 있는지 검사한다. 있으면 사용자에게 키 교체를 알린다(교체는 사용자가 한다).
- [ ] 11-3 Fly 배포 이미지에 .env · 데이터 · 시험 파일이 들어가지 않는지 본다(.dockerignore).

## 12. 감시 · 기록
- [ ] 12-1 보안 사건 기록: 속도 제한에 걸림 · 거절된 기록 · 주입 의심 · Origin 거절을 모은다. 개인정보는 빼고, IP 는 해시로.
- [ ] 12-2 관리자 화면에 하루 요약(종류별 건수 · 상위 IP 해시)을 보인다.
